# Deployment Note

## Recommended Production Architecture

For a stable production environment, use:

- **Frontend**: Static hosting (Vercel, Cloudflare Pages, GitHub Pages, etc.)
- **Backend**: A permanent Python host for `backend/main.py` (Render, AWS, DigitalOcean, etc.)

This setup ensures that the frontend remains fast and the backend logic stays consistent with the development environment.

## Current Direction

- **Frontend**: Deploy the `frontend/dist` directory (generated by `npm run build`) to your preferred static host.
- **Backend**: Deploy using the provided `render.yaml` or by running `python3 backend/main.py` on a persistent server.
- **API Communication**: Set the `VITE_API_URL` environment variable in your frontend deployment to point to your hosted backend URL (e.g., `https://your-backend.onrender.com`).
- **CORS**: If the frontend is hosted on a different domain from the backend, set `ALLOWED_ORIGINS=*` or an explicit allowlist that includes your deployed frontend origin.

## Vercel + Oracle Option

If you want the frontend on Vercel but still want backend behavior close to localhost, use:

- **Frontend**: Vercel with `frontend/` as the project root
- **Backend**: Oracle Cloud Free Ubuntu VM with Docker Compose
- **Reverse Proxy**: Caddy with automatic HTTPS

## Deployment Checklist

1. **Backend**:
   - Deploy `backend/main.py`.
   - Set required environment variables (`GEMINI_API_KEY`, `SUPABASE_URL`, etc.).
   - If the frontend will be hosted on a different origin, set `ALLOWED_ORIGINS=*` or include the exact frontend URL.
   - Verify that `https://your-backend.com/api/health` returns `{"status":"ok"}`.

2. **Frontend**:
   - Set `VITE_API_URL` to your backend URL.
   - Run `npm run build` in the root or `frontend/` directory.
   - Deploy the resulting `frontend/dist` folder.

3. **Verification**:
   - Confirm chat, document upload, and canvas features work as expected on the live URL.
